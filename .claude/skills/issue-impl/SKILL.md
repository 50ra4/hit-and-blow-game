# issue-impl スキル

引数として渡された GitHub Issue 番号を起点に、**計画 → ユーザー承認 → 実装** の全工程を実行する。

## 使い方

```
/issue-impl <issue番号>
```

## 実行手順

### Step 1: Issue 情報の取得

以下のコマンドで Issue の詳細を取得する。

```bash
gh issue view <issue番号> --json number,title,body,labels,assignees,milestone,state
```

Issue の内容を読み込み、以下を把握する：

- **目的**: Issue が解決しようとしている問題・ユーザーストーリー
- **受け入れ条件**: 完了の定義（Acceptance Criteria）
- **スコープ**: 影響を受ける機能・ページ・コンポーネント

### Step 2: コードベース調査

Issue の内容に基づき、影響を受ける既存コードを調査する。

- README.mdを確認する
- 関連ファイル・コンポーネントを特定する
- 既存の実装パターン・依存関係を把握する
- 変更が必要なファイルをリストアップする

### Step 3: 実装計画の立案（Plan Mode）

`EnterPlanMode` を使い、以下の内容を含む計画ファイルを `.claude/plans/issue-<番号>-<タイトル>.md` に出力する。

#### 計画ファイルのフォーマット

```markdown
# Issue #<番号>: <タイトル>

## 概要

<Issue の目的・解決する問題を1〜2文で要約>

**意図（なぜ必要か）**: <Issue が生まれた背景・ユーザーへの価値>

**選択理由**: <技術的アプローチの選択理由・代替案との比較>

---

## 変更ファイル

| ファイル           | 変更内容   |
| ------------------ | ---------- |
| `path/to/file.tsx` | 変更の概要 |

---

## タスク

### Task 1: <タスク名>

#### 受け入れ条件

- [ ] 条件1
- [ ] 条件2

#### 実装詳細

<具体的な実装手順・コード例・注意事項>
```

#### 注意点

不明点・矛盾点は、憶測ではなく随時確認する。

出力したファイルは都度コミットすること。

実装は、モデル`Haiku 4.5`が行うこともあるため、`Haiku 4.5`でも実装できる文章で出力する。

Issueの内容に応じて、次のモデルに指示する。

- 複雑な計画は、モデル`opus 4.6`を使用する
- 簡単な計画は、モデル`sonnet 4.6`を使用する

### Step 4: ユーザー承認

`ExitPlanMode` でユーザーに計画を提示し、承認を得る。

### Step 5: 実装

ユーザー承認後、計画に沿って実装を行う。

実装した計画の内容に応じて、次のモデルに実装を指示すること。

- 複雑な実装は、モデル`sonnet 4.6`を使用する
- 簡単な実装は、モデル`haiku 4.5`を使用する

**必須事項**:

1. `/coding-conventions` を参照し、コーディング規約に従う
2. i18n テキストが必要な場合は `ja.json` と `en.json` の両方に追加する
3. タスクごとに動作確認しながら進める
4. タスクごとにコーディング規約の Git コミットメッセージ規約に従い、都度コミットする

   ```
   <type>: [ISSUE <番号>] <subject>

   <body: Why（なぜこの変更が必要だったか）>
   ```

5. 実装完了後に `/coding-conventions` スキルでコードを見直す
6. 全てのタスクを実装完了後、モデル`sonnet 4.6`が受け入れ条件の検収を行う

## 注意事項

- 最初に最新のmainブランチから作業ブランチ（`feature/issue-<番号>-<概要>`）を作成する
- 計画ファイルには **意図**（なぜ必要か）と **選択理由** を必ず記載する
- その他の作業ルール・コーディング規約は `.claude/rules/` を参照
