# issue-impl スキル

引数として渡された GitHub Issue 番号の **実装計画に基づき、コード実装を行う**。

## 使い方

```
/issue-impl <issue番号>
```

## 実行手順

### Step 1: 計画ファイルの確認

`<PROJECT_ROOT>/.claude/plans/issue-<番号>*.md` の存在を確認する。

- **存在しない場合**: `/issue-plan <番号>` スキルを **必ず** 先に実行する。計画が完成するまで実装に進んではならない。
- **存在する場合**: 計画ファイルを読み込み、Step 2 に進む。

### Step 2: タスクリストの作成

計画ファイルのタスク一覧を `TaskCreate` で登録する。全タスクを登録してから実装に着手する。

### Step 3: タスクごとの実装

各タスクについて以下を **必ず** 実行する。1つでも省略してはならない。

1. `TaskUpdate` でタスクを `in_progress` に更新する
2. `/coding-conventions` スキルでコーディング規約を確認する
3. 計画ファイルの実装詳細に従いコードを実装する
4. 動作確認（型チェック・lint等）を行う
5. コミットする（フォーマットは下記参照）
6. `TaskUpdate` でタスクを `completed` に更新する

#### コミットメッセージフォーマット

```
<type>: [ISSUE <番号>] <subject>

<body: Why（なぜこの変更が必要だったか）>
```

#### モデル委譲

タスクの複雑さに応じて、Agent ツールで以下のモデルに実装を委譲する：

| 判定 | モデル   | 基準                                                                |
| ---- | -------- | ------------------------------------------------------------------- |
| 複雑 | `sonnet` | 新規コンポーネント作成、ロジック変更、複数ファイル連携、テスト作成  |
| 単純 | `haiku`  | 定数変更、i18nテキスト追加、既存パターンの踏襲、1ファイル完結の変更 |

Agent に委譲する際は、計画ファイルの該当タスクの内容を **そのまま** プロンプトに含める。

### Step 4: 受け入れ条件の検収

全タスク完了後、モデル `sonnet` の Agent で以下を検証する：

1. 計画ファイルの受け入れ条件を全て満たしているか確認
2. `pnpm type-check` が通ることを確認
3. `pnpm lint` が通ることを確認

## 必須事項

- i18n テキストが必要な場合は `ja.json` と `en.json` の **両方** に追加する
- 実装完了後に `/coding-conventions` スキルでコードを見直す
- コーディング規約は `.claude/rules/` を参照

## 注意事項

- 作業ブランチが未作成の場合は、最新の main ブランチから `feature/issue-<番号>-<概要>` を作成する
- 計画ファイルに記載のないスコープ外の変更は行わない
