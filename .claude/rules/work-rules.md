# 作業ルール

## ブランチ運用

- main ブランチへの直接コミットは**禁止**。必ず作業ブランチを切ること。

## ドキュメント

- DRY の原則を遵守。情報を書くべきファイルに集約し、参照先を記載する。

## コーディング規約

- 実装前に必ずコーディング規約を確認すること（`.claude/rules/` 配下の各ルールファイルを参照）。
- `/coding-conventions` スキルでも一覧を確認可能。

## Plan Mode

- 作成した計画は `.claude/plans/` にファイル出力する。
- プランファイルに**意図**（なぜ必要か）と**選択理由**を含め、後からレビューできるようにする。

## スタイル

> コードには `How`、テストには `What`、コミットログには `Why`、コメントには `Why not`

- コメントは「なぜこの実装を選んだか・他の選択肢を取らなかったか」を書く
- How（コード自体が説明している内容）は書かない
- 型で自明な場合は省略
